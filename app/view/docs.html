API 文档

本站对外提供 OpenAI 兼容接口：把你代码里的 base_url 换成下面的地址、 把 API Key 换成你的令牌，其余不用改。

去控制台拿令牌 登录

接入地址（Base URL）

注意地址末尾的 /v1 要带上。OpenAI 官方 SDK 里这一项叫 base_url（Python）或 baseURL（Node）， 不要再自己拼 /chat/completions。

认证

所有接口都需要带令牌（在 用户控制台 里创建）：

Authorization: Bearer 你的令牌

令牌是你的身份：它决定用哪个账号扣费、能调用哪些模型。 不要把它写进前端代码或公开仓库 —— 泄露等于把余额交给别人。

缺令牌或令牌无效时返回 401，响应体是 OpenAI 风格的 JSON： 

{"error":{"message":"...","type":"invalid_request_error","code":"invalid_api_key"}}

可用端点

GET/v1/models

列出你这把令牌能用的模型。客户端常用它做模型下拉框。

curl /models \
  -H "Authorization: Bearer 你的令牌"
{
  "object": "list",
  "data": [
    {"id": "模型名", "object": "model", "created": 1737000000, "owned_by": "", "priced": true}
  ]
}

其中 priced 是本站附加的字段：表示这个模型有没有单独定价， 客户端可以忽略它。

POST/v1/chat/completions

对话补全，支持流式与非流式。请求体与 OpenAI 一致：

字段说明
model模型名，从「模型广场」或 /v1/models 里取
messages对话数组，元素形如 {"role":"user","content":"你好"}
streamtrue 时以 SSE 逐块返回；false 或不传则一次性返回
max_tokens可选，限制回答长度
temperature可选，采样温度

其余字段会原样透传给上游；本站还可能按站长配置给请求附加参数 （例如某些上游要求的版本号），你不需要关心。

示例代码

curl

curl /chat/completions \
  -H "Authorization: Bearer 你的令牌" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "",
    "messages": [{"role": "user", "content": "你好"}],
    "stream": false
  }'

Python（openai 官方 SDK）

from openai import OpenAI

client = OpenAI(
    base_url="",
    api_key="你的令牌",
)

resp = client.chat.completions.create(
    model="",
    messages=[{"role": "user", "content": "你好"}],
    timeout=,   # 慢模型要把超时调大，见下方「常见问题」
)
print(resp.choices[0].message.content)

Node（openai 官方 SDK）

import OpenAI from 'openai';

const client = new OpenAI({
  baseURL: '',
  apiKey: '你的令牌',
});

const resp = await client.chat.completions.create({
  model: '',
  messages: [{ role: 'user', content: '你好' }],
});
console.log(resp.choices[0].message.content);

流式输出

传 "stream": true 后，服务端按 SSE 逐块推送， 每块形如 data: {...}，结束时发一行 data: [DONE]： 

data: {"choices":[{"delta":{"content":"你"}}]}
data: {"choices":[{"delta":{"content":"好"}}]}
data: [DONE]

用官方 SDK 时不需要自己解析 SSE，直接 for chunk in stream: 即可。 长回答会由服务端定期发送心跳保活，中途断开通常是客户端超时设置太短。

错误码与处理建议

状态码含义与建议动作
401
invalid_api_key		 令牌缺失、无效、已停用或已过期。只需检查密钥本身： 确认用的是本站令牌（以 sk-aqua- 开头）、复制时没带空格或换行、 请求头是 Authorization: Bearer <令牌>。
402
insufficient_balance		 令牌是好的，余额不够。去控制台看余额， 充值（或在「用量报表」里确认消费）后即可继续调用。 这一条与 401 分开，就是为了不让人拿着好密钥反复排查。
403
insufficient_quota
account_disabled
model_not_allowed		 令牌额度已用完（可到控制台「清额度」或新建令牌）、账号被站长停用、 或该令牌的模型白名单里没有这个模型。
404模型名不存在或当前渠道不支持。用 /v1/models 取准确名称。
401 / 403
且 type 为 upstream_error		 这不是你的问题：本站到上游的请求被拒了（上游把我们的密钥停了、或该模型对本站账号无权限）。 本站会自动换渠道/换密钥重试，仍失败请把报错发给站长。
429触发上游或本站限流。稍后重试，或降低并发。
503当前没有可用渠道服务这个模型（渠道被禁用或熔断）。请稍后重试或联系站长。
5xx上游异常。本站会自动换渠道重试；仍失败时请稍后再试。
超时模型响应慢（免费渠道常见）。把客户端超时调到 60-120 秒，或换响应更快的模型。

计费与限额

  • 计费单位是 ；按 Token 或按次计价，具体以「模型广场」上标的价格为准。
  • 标着「免费」或「未定价」的模型当前不扣费。
  • 每次调用的用量与费用都会记进控制台的「最近调用」，可以核对。
  • 令牌可以单独设额度，用完之后该令牌会失效 —— 适合给子账号或临时试用。
  • 上游可能对单账号限速；本站会把请求分配到渠道下的多把密钥上。

常见问题

  • 「我应该用哪个模型名？」
    打开 模型广场，卡片上写着的就是准确名称，点「复制」即可。 也可以调 /v1/models 拿你自己的可用清单。
  • 「为什么很慢 / 报超时？」
    免费渠道的模型首包可能要十几秒（模型在冷启动）。把客户端超时调到 秒以上通常就能解决； 模型广场上的速度色标可以帮你挑快的。 本站单请求总时长上限是 秒。
  • 「401 了怎么排查？」
    先确认令牌没被停用、没有写错（复制时别带空格）；再确认请求头是 Authorization: Bearer <令牌>，而不是 api-key。
    如果错误里写的是余额不足，那是 402 不是密钥问题 —— 去控制台充值即可，令牌不用换。
  • 「同一个账号多人用会互相影响吗？」
    会共用账号余额。要区分用量就给每个人单独建一把令牌，额度分开设。
