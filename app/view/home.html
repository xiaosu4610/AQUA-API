这个网关做了什么

把「对接多家上游」这件事从你的应用里挪出来，统一在一层解决。

接口兼容，改一行就能用

遵循 OpenAI 的 /v1/chat/completions 与 /v1/models， 现有的 SDK、客户端、脚本只需换掉 base_url 与 Key。

原生流式，不缓冲

基于事件循环的转发引擎，逐块透传上游数据。上游返回 401 / 429 / 5xx 时 你收到的是真实状态码，而不是伪装成 200 的错误流。

多上游与密钥池

一个模型可挂多家上游，按优先级与权重分流；单个上游可挂上百把密钥轮换， 单把限流、失败自动冷却、失效自动停用。

故障自动切换

上游超时、限流、报错时自动换一条线路重试；某条线路连续失败会被短期熔断， 不会让每个请求都去撞一次墙。

用量与计费

按 Token / 按次 / 订阅 / 免费四种口径计费，上游成本与下游售价分开记录， 每一笔调用都能回溯到具体模型与线路。

可观测

每次请求的 token、耗时、状态、成败都有记录；控制台可看余额与调用明细， 接口出问题时能直接定位到是哪一段。

快速开始

在控制台创建令牌后，把下面的 Key 换成你自己的即可。 登录后在控制台创建令牌，再按下面的方式调用。 

# 1) 查看可用模型
curl /v1/models \
  -H "Authorization: Bearer $AQUA_KEY"

# 2) 发起一次对话（流式）
curl /v1/chat/completions \
  -H "Authorization: Bearer $AQUA_KEY" \
  -H "Content-Type: application/json" \
  -d '{
        "model": "",
        "stream": true,
        "messages": [{"role": "user", "content": "你好"}]
      }'

# 3) 用官方 SDK 也行（Python）：只改 base_url
# client = OpenAI(base_url="/v1", api_key="...")

认证方式与 OpenAI 一致（Authorization: Bearer <令牌>）， 也接受 x-api-key 头。
