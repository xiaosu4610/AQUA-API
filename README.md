# aqua-api-php

小型 LLM API 资源管理网关。

## 这是什么

对外提供一套 **OpenAI 兼容接口**，对内管理多家上游的密钥池、路由、用量与配额。

适合这些场景：自用、团队内部共享、以及自建免费共享（公益）站。

> **当前状态：v0.1.0 已发布** —— 可用的最小完整版本（转发引擎 + 计费 + 下游用户体系 + 管理后台）。
> 下载见 [Releases](https://gitee.com/xiaosu4610/aqua-api-php/releases)。

## 特性规划

- **统一接口**：OpenAI 兼容（含流式 SSE），调用方改 `base_url` 即可接入
- **多上游密钥池**：轮询 / 加权随机 / 失败跳过 / 冷却后恢复
- **渠道路由**：优先级 + 权重、故障自动重试与降级
- **令牌与配额**：模型白名单、IP 白名单、分级限流
- **用量统计**：调用日志、模型消耗、异常归因
- **NVIDIA NIM 专项优化**：限流令牌桶、SSE 首帧闸门、超时分层、动态目录同步
- **接入简单**：填一个 API Key 即可跑通

## 技术栈

| 项 | 选择 |
|---|---|
| 语言 | PHP >= 8.1（开发与生产使用 **PHP 8.4**） |
| 运行时 | [Webman](https://www.workerman.net/webman)（基于 Workerman 的常驻内存框架） |
| 数据库 | SQLite（默认，零配置）或 MySQL |
| 入口 | 内置 HTTP 服务；需要域名 / TLS 时前置 Nginx 反向代理 |

> **为什么不用 PHP-FPM**：本项目的核心请求是**长连接流式转发**。PHP-FPM 的「一请求一进程」模型会让一条流独占一个 worker 直到生成结束，并发上限很低。Webman 是常驻内存 + 事件循环，且**不需要安装任何 PHP 扩展**即可运行。

## 快速开始

```bash
composer install
php start.php start
```

Windows 下直接运行：

```
windows.bat
```

默认监听 `http://127.0.0.1:8787`。

> Linux 下多进程运行需要 `pcntl` 与 `posix` 扩展（标准 PHP CLI 通常自带）。
> 并发连接数大于 1024 时，建议安装 `event` 扩展以获得 epoll 支持。

## 管理后台

后台入口是 **`/admin/login`**，只需要密码，不需要用户名。

> **刻意不在站点页面上放后台链接。** 首页、登录页、安装向导里都没有任何指向后台的
> 入口 —— 没有任何理由主动把地址公告给扫描者。这个地址本身**不是**你的安全防线
> （默认路径写在代码里、公开可查）：真正的防线是强密码 + 登录失败锁定 + HTTPS。
> 所以请部署完务必读下一节的加固清单。

首次设置密码见 `.env.example` 的 `ADMIN_PASSWORD`（**仅首次初始化时生效**，
之后改 `.env` 不会覆盖已有密码，请用后台的「修改密码」）。
忘记密码可在服务器上执行：

```bash
php scripts/reset-admin-password.php
```

## 安全与部署加固

上线前请逐条确认：

1. **HTTPS 必须开启** —— 会话 Cookie 的 `secure` 属性只有在 HTTPS 下才有意义
2. **`APP_DEBUG=false`** —— 生产环境设成 `true` 会把异常堆栈返回给客户端
3. **屏蔽安装向导** —— 装完后在 Nginx 层直接 404 掉 `/install` 与 `/install.php`
   （应用层另有锁文件双保险，但网络层直接不可达更干净）
4. **数据库只监听 127.0.0.1** —— MySQL 官方包默认监听 `*:3306`，等于对公网暴露
5. **`.env` 权限 600**，属主为服务进程用户
6. **`APP_KEY` 一旦设定不可再改** —— 换了它，所有已加密的上游 Key 都会失效
7. **后台口令用独立强密码** —— 与服务器 SSH 口令同值属于「凭据复用」，
   一处泄露等于两处沦陷
8. 建议关闭 SSH 密码登录、启用防火墙（仅放行 80 / 443 / SSH）

### 凭据绝不进代码

本项目是**公开仓库**。上游 API Key、SMTP 授权码、支付商户密钥、
数据库口令、`APP_KEY` —— 一律通过后台填写（敏感项加密入库、后台只显示「已配置」）
或 `.env` 注入，**绝不写进源码**。凭据一旦进了提交，那一刻就等于公开，
而且进了 git 历史就收不回。

## 目录结构

```
app/        应用代码（控制器、中间件、业务逻辑）
config/     配置
public/     Web 入口 —— 站点运行目录必须指向这里，否则敏感文件可能被直接访问
runtime/    运行时数据（日志、缓存），不入版本库
support/    框架支撑代码
```
