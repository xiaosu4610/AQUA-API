## 这是什么

AQUA-API 是一个**自托管的 LLM API 网关**，同时是一套**AI 资产（用量）管理系统**。

上游是你手上一堆互不兼容的东西：OpenAI 官方 Key、Azure、Claude、Gemini、各家云厂商、
各种中转站、订阅来的账号（Claude / Codex / Gemini）、以及本地跑的 Ollama / vLLM。
下游是你的应用：Claude Code、Codex CLI、Cursor、自研 App、脚本、插件。

AQUA-API 站在中间，把这一切整理成**一个入口、一套协议、一本清楚的账**。

## 为什么不是"又一个中转站"

| | 常见做法 | AQUA-API |
|---|---|---|
| **上游密钥** | 明文存数据库，界面能看回明文 | **AES-256-GCM 加密落库**，密钥只从环境变量注入；后台被攻破也拿不到明文 |
| **主密钥** | 一并写进配置 | 配置文件里的同名字段**直接忽略**，只能走环境变量 —— 密钥不可能随仓库泄露 |
| **上游故障** | 连续失败就永久禁用，池子越用越小 | **冷却 + 半开**：限流只是"临时避让"，到期自动恢复；只有上游明确说"凭据已吊销"才摘除 |
| **限流与并发** | 全局一个阈值 | **按凭据**独立计（权重 / 优先级 / 每分钟上限 / 在途数），超限自动换下一把，不误伤凭据 |
| **额度** | 请求前后各查一次，并发下能透支 | **预扣 → 结算 → 退还**，可用额度 = 额度 − 已用 − 在途；并发也扣不出负数 |
| **协议** | 只做 OpenAI 兼容 | 下游 OpenAI / Anthropic / Gemini 三套协议齐备，上游按类型选适配器 |
| **付费模型** | 密钥即权限，无法区分人群 | **分组**决定可用渠道与价格，**密钥可选分组**：同一份上游，免费人群与付费人群各走各的 |

## 功能全景

### 网关与转发

| 能力 | 说明 |
|---|---|
| 下游协议 | OpenAI 兼容（`/v1/chat/completions`、`/v1/models`、`/v1/embeddings`）、Anthropic、Gemini |
| 上游协议 | OpenAI 兼容、**Azure OpenAI**（部署名 + api-version）、**Anthropic**、**Gemini** |
| 渠道类型目录 | **79 种**上游类型已登记（文本 / 图像 / 视频 / 音频 / 嵌入 / 聚合 / 自建 / 订阅），按类型自动展开该类型专属字段 |
| 流式 | SSE 逐片转发；上游与下游协议不同时**双向转换**（Anthropic / Gemini 事件 ↔ OpenAI chunk） |
| 统一中间表示 | 内部统一收敛到 OpenAI 协议（N×1），新增上游只写"进"、新增下游只写"出" |
| 超时 | 上游等待上限 **300 秒**，长回答不会被掐断 |
| 错误透传 | 上游真实错误原样回传（含 RFC7807 `detail` 与 OpenAI `error.message`），不吞错 |

### 凭据池与调度

| 能力 | 说明 |
|---|---|
| 调度策略 | **顺序 / 轮询 / 加权随机 / 最久未用 / 最少在途**（默认最少在途），渠道级可配 |
| 凭据级参数 | 权重、优先级、每分钟上限、在途数、冷却截止时间，后台可逐个调 |
| 失败处理 | 429 / 5xx → 短冷却（指数退避）；401 / 403 / 402 → 长冷却；**明确无效才摘除**；连接层失败不计入 |
| 会话粘性 | 同会话固定同一把凭据（利于上游缓存命中）；目标失效自动放弃并清除绑定 |
| 多密钥录入 | 单条 / 批量粘贴 / 多合一 |

### 计费与账务

| 能力 | 说明 |
|---|---|
| 计费口径 | `额度 = (输入 Token × 输入价 + 输出 Token × 输出价) / 1,000,000`，另支持**按次计价** |
| 价格规则 | 按模型名或**通配模式**匹配，可挂到分组；带内存缓存，改价即时生效 |
| 额度安全 | 预扣 + 结算 + 退还；不计费模型**跳过预扣**（免费模型不会被额度墙挡住） |
| 额度语义 | `-1` 表示不限；判定用"剩余 ≤ 0"而非"== 0"，堵住超额透支 |
| 支付通道 | 人工确认 / 易支付 / **Stripe** / **支付宝官方**（RSA2 签名）/ **微信支付官方**（APIv3 + 平台证书验签 + AES-GCM 解密） |
| 兑换码 | 批量生成、并发兑换单事务原子扣减（10 并发抢同一码只会成功一次） |
| 订单账务 | 回调验签、幂等入账、人工补单 / 关单 / 退款 |

### 运营与后台

| 能力 | 说明 |
|---|---|
| 界面入口 | **用户站**（落地页 / 模型广场 / 控制台）· **管理后台**（`/admin`） |
| 模型广场 | 分面筛选（分组 / 厂商 / 可用状态）+ 分面计数联动 + 搜索 + 排序 + 卡片/列表双视图 + 详情弹窗（含价格表与可运行的 cURL） |
| 渠道管理 | 增删改、连通性测活、密钥池抽屉、**一键从上游拉取模型列表** |
| 分组 | 分组实体 + 计费倍率 + 引用统计（删除前告诉你影响多少渠道与价格） |
| 令牌 | 额度 / 过期 / 模型白名单 / **所属分组**；创建时明文只展示一次 |
| 异步任务 | 生成类任务提交、轮询、取消；按次计价；失败自动退还 |
| 兑换码 / 订单 / 日志 / 用户 / 订阅账号 | 全套后台页面 |
| 移动端 | 底部导航、表格自动降级为卡片、安全区适配、弹窗底部弹出 |

## 🚀 60 秒跑起来

```bash
git clone https://gitee.com/xiaosu4610/AQUA-API.git
cd AQUA-API

go build -o aqua ./cmd/aqua     # 纯 Go，零 CGO，不需要 gcc
./aqua -gen-key                 # 生成加密主密钥（渠道密钥靠它加密落库）

export AQUA_APP_KEY="<上一步生成的密钥>"   # Windows: $env:AQUA_APP_KEY="..."
./aqua                          # 默认 127.0.0.1:8787，SQLite 自动建库并执行迁移
```

浏览器打开 `http://127.0.0.1:8787` —— 落地页、模型广场、控制台、管理后台全都在里面。

> 前端已内嵌进二进制（`go:embed`），**部署只需要一个文件**；数据默认落在 `./data/aqua.db`。
> 主密钥请务必单独备份：**它一变，已加密的上游密钥就再也解不开了**。

## 配置

优先级：**默认值 < 配置文件 < 环境变量**。

| 变量 | 必填 | 说明 |
|---|---|---|
| `AQUA_APP_KEY` | ✅ | 加密主密钥，**只能走环境变量**（配置文件里的同名字段会被忽略）。`aqua -gen-key` 生成 |
| `AQUA_SERVER_LISTEN` | | 监听地址，默认 `127.0.0.1:8787` |
| `AQUA_DATABASE_DRIVER` / `AQUA_DATABASE_DSN` | | 默认 `sqlite` / `./data/aqua.db` |
| `AQUA_RELAY_GROUP` | | 网关**默认分组**（不带分组的令牌走哪个分组），默认 `default` |
| `AQUA_SMTP_*` | | 邮件发信（注册验证码 / 通知） |
| `AQUA_EPAY_KEY`、`AQUA_STRIPE_SECRET_KEY`、`AQUA_ALIPAY_PRIVATE_KEY`、`AQUA_WECHATPAY_APIV3_KEY` … | | 各支付通道密钥，**全部只走环境变量** |
| `AQUA_LOG_LEVEL` / `AQUA_LOG_FORMAT` | | `debug`/`info`/`warn`/`error`，`text`/`json` |

**设计原则：密钥类配置一律不入库。** 支付、SMTP、加密主密钥都只能从环境变量注入，
运营参数（网关地址、商户号、汇率、限额、开关）才进数据库、后台可改。

## 接口一览

| 组 | 路径 |
|---|---|
| 公开 | `/healthz`、`/api/models`（模型广场）、`/api/auth/*`、支付回调 |
| 需登录 | `/api/user/*`、`/api/user/tokens`、`/api/user/orders`、`/api/user/redeem` |
| 需管理员 | `/api/admin/*`（渠道 / 凭据 / 分组 / 模型 / 计价 / 令牌 / 用户 / 订单 / 兑换码 / 任务 / 日志 / 设置） |
| 转发 | `/v1/chat/completions`、`/v1/models`、`/v1/embeddings` |

错误响应遵循 OpenAI 格式，现有 SDK 可直接解析：

```json
{"error":{"message":"当前没有可用的上游渠道能处理该模型","type":"server_error","code":"no_available_channel"}}
```

## 技术选型与取舍

| 选择 | 理由 |
|---|---|
| **纯 Go + 零 CGO** | 一条 `go build` 出单二进制，交叉编译无痛；不依赖 gcc |
| **SQLite（`modernc.org/sqlite`）** | 纯 Go 实现的 SQLite 驱动；自托管场景零运维，备份就是拷一个文件 |
| **手写 SQL + 版本化迁移** | 迁移脚本可审计、可 review；不引 ORM，避免"框架生成的 SQL 没人看得懂" |
| **前端内嵌进二进制** | 部署只需一个文件；不额外暴露静态资源服务 |
| **不强制 Redis** | 单机够用；只有在多实例共享限流时才需要引入 |
| **限流按"IP + 用户"双挂** | 只按 IP 会被代理轮换绕过 |
| **冷却与摘除分开** | "临时限流"和"永久失效"是两件事，混在一起会让凭据池在故障中单调萎缩 |

## 开发

```bash
go build ./...     # 编译
go test ./...      # 测试
gofmt -w .         # 格式化
```

工程约定（**强制**）：

1. **小步提交** —— 每个可独立描述的小步骤完成后立刻提交，禁止攒到最后一次性提交。
2. **注释面向 AI 友好** —— 每个源文件头部必须写清「意图 / 流转 / 扩展」三段，让任何人（或 AI）30 秒内看懂这个文件干什么、怎么流转、往哪扩展。

详见 [`AGENTS.md`](AGENTS.md)。

### 目录结构

```
cmd/aqua/           程序入口（仅装配，不含业务逻辑）
internal/config/    配置加载与校验
internal/model/     领域模型与仓储接口
internal/store/     持久化实现（SQL + 版本化迁移）
internal/server/    HTTP 层（路由 / 中间件 / 处理器）
internal/relay/     协议适配与转发（核心域）
internal/payment/   支付通道适配
internal/channeltype/ 上下游类型注册表
web/                前端（构建产物内嵌进二进制）
```
