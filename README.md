# aqua-api-php

小型 LLM API 资源管理网关。

## 这是什么

对外提供一套 **OpenAI 兼容接口**，对内管理多家上游的密钥池、路由、用量与配额。

适合这些场景：自用、团队内部共享、以及自建免费共享（公益）站。

> **当前状态：开发中**，尚无可用版本。

## 特性规划

- **统一接口**：OpenAI 兼容（含流式 SSE），调用方改 `base_url` 即可接入
- **多上游密钥池**：轮询 / 加权随机 / 失败跳过 / 冷却后恢复
- **渠道路由**：优先级 + 权重、故障自动重试与降级
- **令牌与配额**：模型白名单、IP 白名单、分级限流
- **用量统计**：调用日志、模型消耗、异常归因
- **NVIDIA NIM 专项优化**：限流令牌桶、SSE 首帧闸门、超时分层、动态目录同步
- **接入简单**：填一个 API Key 即可跑通

## 技术栈

| 项 | 选择 |
|---|---|
| 语言 | PHP >= 8.1（开发与生产使用 **PHP 8.4**） |
| 运行时 | [Webman](https://www.workerman.net/webman)（基于 Workerman 的常驻内存框架） |
| 数据库 | SQLite（默认，零配置）或 MySQL |
| 入口 | 内置 HTTP 服务；需要域名 / TLS 时前置 Nginx 反向代理 |

> **为什么不用 PHP-FPM**：本项目的核心请求是**长连接流式转发**。PHP-FPM 的「一请求一进程」模型会让一条流独占一个 worker 直到生成结束，并发上限很低。Webman 是常驻内存 + 事件循环，且**不需要安装任何 PHP 扩展**即可运行。

## 快速开始

```bash
composer install
php start.php start
```

Windows 下直接运行：

```
windows.bat
```

默认监听 `http://127.0.0.1:8787`。

> Linux 下多进程运行需要 `pcntl` 与 `posix` 扩展（标准 PHP CLI 通常自带）。
> 并发连接数大于 1024 时，建议安装 `event` 扩展以获得 epoll 支持。

## 目录结构

```
app/        应用代码（控制器、中间件、业务逻辑）
config/     配置
public/     Web 入口 —— 站点运行目录必须指向这里，否则敏感文件可能被直接访问
runtime/    运行时数据（日志、缓存），不入版本库
support/    框架支撑代码
```
